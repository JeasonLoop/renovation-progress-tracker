# 装修进度与调研助手：需求分析（草案）

- 文档日期：2026-07-28
- 文档状态：待用户评审
- 产品阶段：需求分析，尚未进入开发
- 暂定名称：装修进度与调研助手

## 1. 背景与目标

首次装修的人通常同时面对四类困难：不知道完整流程，不知道每个节点该检查什么，现场信息散落在聊天、相册和表格中，以及完工后很难形成可追溯的档案。本产品希望把“学习、计划、执行、验收、记录、复盘”放在一个网站中，让用户随时知道当前做到哪里、下一步做什么、哪些细节有风险、钱花到了哪里。

### 1.1 核心目标

1. 用阶段、任务和里程碑清晰展示装修总体进度。
2. 为关键工序提供足够细致、易理解的调研与验收清单。
3. 集中保存文字、照片、票据、材料参数、费用和决策依据。
4. 对延期、超预算、未验收、待整改等风险进行提示。
5. 支持将核心数据导出，便于备份、打印、对账和维权。

### 1.2 非目标（首版不做）

- 不做装修公司撮合、建材商城或广告推荐平台。
- 不替代设计师、监理、结构工程师等专业人员给出安全结论。
- 不做多人组织、复杂权限、在线合同签署和在线支付。
- 不追求一次覆盖所有地区的政策、报价和施工规范。

## 2. 目标用户与使用场景

### 2.1 核心用户

准备装修或正在装修的个人业主，装修经验少，以手机查看和现场记录为主，同时会在电脑上做集中整理、材料对比和数据导出。

### 2.2 高频场景

- 开工前：创建项目、填写房屋情况、选择装修方式、生成阶段模板和初始预算。
- 每日查看：确认当前阶段、今日任务、临近节点、未处理问题和预算变化。
- 现场巡查：拍照、写施工日志、勾选验收项、记录尺寸与读数、创建整改问题。
- 购买材料：保存候选商品，比较品牌、型号、价格、规格、环保等级、交期和售后。
- 节点验收：按空间和工序逐项检查，附照片证据，记录结论与整改期限。
- 对账复盘：核对预算、合同、付款、增项、票据，导出完整项目档案。

## 3. 产品方案比较

### 方案 A：轻量进度看板

只提供阶段、任务、笔记和简单导出。开发快、学习成本低，但无法满足“细致调研”和完整留档，后续容易重新设计数据结构。

### 方案 B：本地优先的个人装修管理站（推荐）

围绕单个业主建立完整项目档案，包含进度、知识与验收、材料对比、费用、日志、问题和导出。先保证单人使用顺畅，数据默认保存在浏览器或本地数据库，并提供完整备份文件。它最贴合当前需求，成本和完整度平衡最好。

### 方案 C：云端多人协作平台

业主、家人、设计师、工长和监理共同使用，带账号、权限、评论与通知。协作能力强，但登录、权限、文件存储、隐私和运维成本显著增加，不适合作为第一版起点。

### 结论

建议采用方案 B，同时在数据模型中保留未来同步与多人协作的扩展空间。首版先验证个人是否愿意持续记录，以及细致清单是否真的帮助现场决策。

| --- | --- | --- |

## 5. 功能需求

### 5.1 项目初始化

- 创建装修项目：项目名、地址别名、建筑/套内面积、户型、装修方式、计划开工与完工日期、总预算。
- 隐私考虑：地址默认使用别名，不强制填写精确门牌号。
- 可选装修范围：全屋、局部改造、毛坯、旧房翻新。
- 根据范围生成可编辑的默认阶段：准备与设计、拆改、新建、水电、泥瓦、木作、油漆、安装、软装、开荒与入住。
- 每个阶段可设置是否适用，避免无关任务干扰。

### 5.2 进度管理

- 阶段状态：未开始、进行中、待验收、已完成、已暂停。
- 任务字段：标题、说明、所属阶段、空间、负责人名称、计划/实际日期、优先级、状态、完成度、前置任务、标签、附件。
- 支持列表、阶段看板和时间轴三种视图；手机端默认列表，电脑端可用时间轴。
- 总进度默认按已完成任务权重计算，允许用户手工调整任务权重。
- 明确区分计划日期与实际日期，自动显示提前或延期天数。
- 里程碑示例：开工交底、水电定位、水电验收、防水闭水、瓷砖验收、墙面验收、竣工验收。
- 首页显示未来 7 天任务、已逾期任务、待验收节点和阻塞任务。

### 5.3 调研知识库（细致重点）

知识条目不能只有长篇文章，应按“为什么重要、开工前确认、施工中观察、验收方法、常见问题、需要留存的证据、何时找专业人员”结构呈现。内容至少覆盖：

- 设计准备：生活习惯清单、插座与照明规划、家具家电尺寸、收纳、动线、适老与儿童安全。
- 拆改：承重结构风险、物业报备、垃圾清运、旧管线保护。
- 水电：回路规划、线径与负载、强弱电间距、管路走向、打压测试、排水坡度、点位高度、封槽前影像。
- 防水：基层处理、涂刷高度与遍数、门槛处理、闭水时间、楼下观察、渗漏记录。
- 泥瓦：瓷砖批次、排版、找坡、空鼓、平整度、阴阳角、地漏坡度、美缝时机。
- 木作与吊顶：材料环保等级、龙骨、检修口、伸缩缝、防潮与防火。
- 油漆墙面：基层、找平、腻子、底漆面漆、色差、开裂、环境温湿度。
- 安装：橱柜、门窗、洁具、五金、开关插座、灯具、地板、家电的尺寸和收口。
- 环保与入住：材料凭证、通风、检测条件、检测报告留档；不对健康风险做无依据保证。

每条知识可被收藏、补充个人笔记，并关联到阶段、任务、材料或验收项。知识内容需标注“通用经验”或“需按当地规范/厂家说明确认”，避免把经验当作强制标准。

### 5.4 验收清单

- 验收模板按“阶段 + 空间 + 检查项”组织，可复制并自定义。
- 检查结果：未检查、合格、不合格、不适用、待确认。
- 检查项字段：目的、工具、操作步骤、参考标准、实测值与单位、照片、备注、检查时间。
- 对“不合格”项一键生成整改问题，并保留从发现到复验的完整记录。
- 重要节点要求至少附一张照片后才能标记完成，此规则可关闭。
- 生成节点验收报告，包含项目、时间、检查项、实测数据、照片、问题和结论。

### 5.5 材料与采购调研

- 建立采购清单：品类、使用空间、计划数量、单位、预算单价、需要到场日期、采购状态。
- 每个品类可保存多个候选方案并横向比较：品牌、型号、规格、颜色、单价、总价、商家、链接、环保/性能参数、质保、交期、退换条件、优缺点、附件。
- 选定某候选后保留其他候选和选择理由，便于回溯决策。
- 状态：待调研、待选定、待下单、已下单、已到货、已验货、已安装、已退换。
- 到货验收记录批次、数量、破损、色差、型号是否一致和现场照片。
- 对超过预算、晚于需求日期到货或质保资料缺失的条目给出提醒。

### 5.6 费用与合同

- 预算按设计、施工、主材、辅材、家具、家电、软装、其他分类，可自定义。
- 记录报价项、合同金额、付款节点、实际支出、退款和增减项。
- 增项必须记录原因、提出方、确认日期、金额和凭证，避免只保留一个总数。
- 显示总预算、已承诺金额、已支付、待支付、剩余预算和超支比例。
- 支出可关联材料、任务、供应商、票据照片和付款方式。
- 本产品只做记录和提示，不承担财务记账或合同法律审查职责。

### 5.7 日志、照片与决策记录

- 施工日志字段：日期、天气（可选）、现场人员、今日完成、明日计划、异常情况、照片。
- 照片支持拍摄时间、空间、阶段、说明和标签；允许同一照片关联多个业务记录。
- 封槽、覆盖或安装前的隐蔽工程照片应标记为“关键证据”。
- 决策记录保存问题、候选方案、最终选择、选择理由、参与人和日期。
- 尺寸记录保存对象、位置、数值、单位、测量方式、草图/照片，减少仅靠文字造成的歧义。
- 联系人记录角色、公司、联系方式和备注；导出时允许排除敏感信息。

### 5.8 问题与整改闭环

- 问题字段：标题、描述、严重程度、发现时间、关联位置/任务/验收项、照片、处理人、期限、状态。
- 状态流转：待处理 -> 整改中 -> 待复验 -> 已关闭；允许标记无法复现或无需处理并填写原因。
- 每次更新形成时间线，不覆盖旧说明和旧照片。
- 逾期、严重且未处理、复验不合格的问题在总览突出显示。

### 5.9 搜索、筛选与提醒

- 全局搜索任务、知识、材料、日志、问题和费用说明。
- 常用筛选：阶段、空间、日期、状态、标签、是否有附件。
- 首版采用站内提醒；浏览器通知和邮件提醒放到后续版本。
- 提醒类型：任务临期、任务逾期、节点待验收、整改到期、付款节点、材料需下单/到货。

### 5.10 存储、备份与导出

- 自动保存用户编辑，避免现场切换页面后丢失内容。
- 第一版建议本地优先存储，并明确显示最近保存时间和存储空间风险。
- 支持导出完整备份包（JSON + 附件），并能重新导入恢复；备份格式必须带版本号。
- 支持 CSV/Excel 导出任务、材料、费用、验收项和问题，方便二次整理。
- 支持生成 PDF 项目报告和单次验收报告；图片较多时提供压缩选项。
- 导出前可选择时间范围、模块和是否包含联系人、地址、付款信息等敏感字段。
- 后续如增加云同步，需提供冲突处理、设备状态和数据删除机制。

## 6. 关键业务规则

1. 阶段完成不等于所有任务完成：若仍有不合格验收项或严重未关闭问题，必须给出明确警告。
2. 删除有关联数据的任务、材料或验收记录时默认归档，避免证据链断裂。
3. 所有金额保存币种；所有测量值保存数值与单位，展示时不能只存拼接文字。
4. 任务、费用、材料、日志、问题和验收记录均保留创建时间与最后修改时间。
5. 重要状态变更保留历史，尤其是验收结论、问题整改和预算增项。
6. 用户自定义模板与内置模板分开保存，产品升级不能覆盖个人修改。

## 7. 核心数据模型

| 实体 | 说明 | 关键关联 |
| --- | --- | --- |
| Project | 一次装修项目 | 拥有全部业务数据 |
| Stage | 装修阶段 | 属于项目，包含任务与验收单 |
| Space | 房间或区域 | 被任务、材料、照片、问题引用 |
| Task | 计划与执行单元 | 关联阶段、空间、附件、问题 |
| KnowledgeItem | 调研知识条目 | 关联任务、材料、验收项 |
| Checklist / CheckItem | 验收单与检查项 | 关联阶段、空间、实测与证据 |
| Material / Candidate | 采购项与候选商品 | 关联费用、空间、到货记录 |
| BudgetItem / Expense | 预算与实际收支 | 关联材料、合同、供应商 |
| Journal | 每日施工日志 | 关联任务、空间、照片 |
| Issue / IssueUpdate | 问题与整改时间线 | 来源可为任务或验收项 |
| Attachment | 照片、票据、合同等文件 | 可被多个实体引用 |
| Decision | 关键选择及其依据 | 关联材料、任务或问题 |
| Contact | 施工方、商家等联系人 | 关联任务、费用、问题 |

数据设计应使用稳定 ID 做关联，不能仅依赖名称；附件应记录类型、大小、校验信息和业务标签，为备份与迁移做准备。

## 8. 核心流程

### 8.1 首次使用

创建项目 -> 填写房屋与预算 -> 选择适用阶段 -> 生成任务/验收模板 -> 进入项目总览。

### 8.2 现场巡查

进入当前阶段 -> 打开任务或验收单 -> 记录实测和照片 -> 标记检查结果 -> 不合格项生成整改 -> 设置复验日期。

### 8.3 材料决策

新建采购项 -> 添加候选 -> 对比参数与总价 -> 记录选择理由 -> 下单 -> 到货验收 -> 关联实际支出。

### 8.4 项目归档

检查未关闭问题与待付款 -> 选择导出范围 -> 生成 PDF 报告、表格和完整备份包 -> 校验备份可重新导入。

## 9. 非功能需求

- 响应式：现场以手机为主，桌面端用于批量编辑和对比；关键操作在 360px 宽度下可用。
- 易用性：使用装修小白能理解的语言，专业术语提供简短解释，不用颜色作为唯一状态信号。
- 性能：常规列表操作即时反馈；图片先生成缩略图，避免总览加载原图。
- 可靠性：编辑自动保存；导入前校验备份版本与结构；恢复操作提供预览和二次确认。
- 隐私：默认不采集精确住址；敏感字段导出可排除；如无云服务，需明确提示清浏览器数据的风险。
- 可访问性：表单有明确标签，支持键盘操作，状态与错误信息可被辅助技术识别。
- 可迁移性：用户能导出机器可读数据，不将项目锁死在单一应用中。

## 10. MVP 范围与迭代建议

### MVP（建议第一版）

- 单项目、单用户、本地优先存储。
- 项目初始化、阶段、任务、总览和站内提醒。
- 可自定义的水电、防水、泥瓦、油漆、安装验收模板。
- 材料候选对比、预算与支出、施工日志、照片、问题整改。
- 全局搜索与基础筛选。
- JSON 完整备份/恢复、CSV/Excel 数据导出、基础 PDF 报告。

### 第二阶段

- 多项目、可安装的 PWA、离线能力、浏览器通知。
- 更丰富的知识模板、空间平面图标注、批量照片整理。
- 云端备份和跨设备同步。

### 第三阶段

- 家庭成员协作、只读分享、施工方提交进度、评论与权限。
- 数据统计、同类材料价格历史、智能生成待办；涉及规范或安全的建议必须保留人工确认。

## 11. MVP 验收标准

1. 用户能在 10 分钟内创建项目并得到一套可编辑的装修阶段与任务。
2. 首页能回答：当前做到哪、下一步是什么、是否延期、是否有待验收或待整改项、预算是否超支。
3. 用户能为一项水电或防水验收记录步骤、结果、实测值、照片，并从不合格项创建整改问题。
4. 用户能对至少 3 个同类材料候选进行字段一致的横向比较并记录最终选择理由。
5. 一笔支出能关联材料或任务，预算总览能区分预算、已承诺、已支付与待支付。
6. 日志、照片和问题能按阶段、空间、日期与状态检索。
7. 完整备份可导出并重新导入，导入后主要实体数量和关联关系一致。
8. 表格导出能被常见表格软件打开，PDF 报告包含必要文字与用户选择的图片。
9. 手机端可完成现场记录、拍照、验收和问题更新，不出现横向溢出或关键按钮不可达。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 功能过多导致用户放弃记录 | 数据不完整，产品失去价值 | 首页提供快速记录；字段分必填与高级项；常用模板预填 |
| 装修标准因地区、材料而不同 | 内容可能误导 | 标注来源与适用条件；区分经验和规范；关键项提示咨询专业人员 |
| 图片占用大量本地空间 | 保存失败或页面变慢 | 压缩、缩略图、容量提示、分模块导出 |
| 浏览器数据被清除 | 项目丢失 | 强提醒定期备份；后续增加云备份 |
| 数据关联复杂 | 导出或恢复后记录断链 | 稳定 ID、版本化备份、导入校验 |
| 预算统计口径混乱 | 用户无法准确判断超支 | 明确定义预算、承诺、已付、应付、退款和增项 |

## 13. 待用户确认的问题

以下选择会影响后续技术方案和首版范围，建议开发前逐项确认：

1. 首版是否接受“数据只保存在当前设备 + 手动备份”，还是必须一开始就支持账号和云同步？
2. 主要在手机使用、电脑使用，还是两者同等重要？
3. 是只管理自己的一套房，还是需要同时管理多套装修项目？
4. 第一版最重要的三个模块是什么：进度、详细验收、材料调研、费用、施工日志、问题整改、导出？
5. 是否需要邀请家人共同编辑，或给施工方一个只允许上传进度的入口？
6. 导出优先级是 Excel、PDF 报告、完整备份，还是三者都必须首发？
7. 是否已有合同、预算表或当前装修资料，需要兼容既有字段并支持导入？
8. 对“细致调研”的期待更偏向工序验收、材料选购、预算报价，还是三者同等深入？

## 14. 开发前建议决策

推荐默认答案是：首版单项目、单用户、手机与电脑响应式、本地优先；核心模块选择进度 + 验收 + 记录，再配材料/费用的基础能力；三种导出都规划，但优先保证 JSON 备份和表格导出可靠，PDF 报告随后完成。确认这些假设后，再进入页面原型、技术选型和详细开发计划。
