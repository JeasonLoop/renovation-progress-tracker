# 技术架构

## 应用结构

应用使用 Next.js App Router，并静态导出到 Cloudflare Worker Static Assets。Worker 在资源之前执行，统一负责管理员认证、受保护附件和安全响应头。客户端工作区持有装修项目状态，各功能视图只接收所需数据和更新函数。

```text
src/
  app/                 路由、布局与全局设计令牌
  components/          应用壳、通用交互组件
  components/views/    总览、进度、验收、预算、调研、记录、导出
  lib/                 类型、示例数据、本地存储与导入校验
worker/                Cloudflare 鉴权、限流、附件和静态资源网关
```

## 数据流

1. 首次打开时加载内置示例项目。
2. 浏览器存在有效的旧版本备份时，优先恢复本地数据。
3. 页面交互通过函数式更新修改统一项目状态。
4. 更新后的状态自动写入 `localStorage`。
5. 用户可以导出完整 JSON，并在同版本应用中重新导入。
6. 数据格式当前为 v4，v1-v3 备份会在读取时自动迁移；旧版已花费金额会保留为历史支出汇总。
7. 图片上传由 Worker 校验会话、来源、大小、MIME 和文件签名后写入私有 KV，业务数据只保存附件引用。

## 认证边界

- 管理员密码使用 PBKDF2-SHA256 派生，仓库和 Worker 配置中不保存明文。
- 登录成功后签发 12 小时 HMAC 签名、HttpOnly、Secure、SameSite=Strict Cookie。
- 登录失败按来源 IP 限制为 15 分钟内 5 次，状态保存在独立 KV。
- 所有页面、业务 API 和附件读取均经过 Worker 会话验证；只有登录页和静态运行文件公开。
- 业务清单仍是单设备本地优先，登录不等于跨设备数据同步。

## 附件模型

`Attachment` 统一记录文件 ID、名称、受保护 URL、MIME、大小和上传时间，并可关联验收、日志、整改问题、材料候选及预算项。Cloudflare 账户启用 R2 后，可保持 API 不变，将当前 KV 存储适配替换为 R2。

## 预算模型

- `budgetCategories` 保存可扩展的预算分类。
- `budgetItems` 分别记录原预算、预算调整、合同金额、已支付、付款日期和供应商。
- 待支付与总览金额由明细实时计算，完整 JSON 和预算 CSV 均包含预算数据。

## 设计系统

- 视觉方向：现场工作手册，强调清晰、可信与可扫描。
- 基础色：冷白、石墨灰；品牌强调色为安全橙。
- 圆角规则：内容容器 8px，按钮和输入框 6px，小标签 5px。
- 动效：只使用悬停、按压和状态切换反馈，并尊重减少动态效果设置。
- 响应式：桌面端固定侧栏；768px 以下为单列内容和底部导航。

## 后续演进

如需跨设备同步，可以保持现有 `RenovationData` 结构，在存储层后增加数据库与身份认证。附件应从本地 Data URL 迁移到对象存储，并保留稳定 ID 与备份版本号。
